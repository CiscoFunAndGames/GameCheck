# Security & Privacy Policy (`SECURITY.md`)

**RigCheck Optimizer** is designed from the ground up with a **local-first, zero-telemetry, read-only architecture** that respects user privacy, system stability, and anti-cheat integrity.

---

## 1. 100% Local, Read-Only Hardware & Display Detection

- **No Telemetry or Analytics**: RigCheck Optimizer does **not** include any analytics SDKs, crash reporters, tracking pixels, or background telemetry services.
- **Local Hardware & Display Inspection Only**:
  - On **Windows (`win32`)**, hardware and display specifications are queried locally in read-only mode via the compiled C++17 native probe (`bin/rigcheck-native-probe.exe` using Win32 `EnumDisplayDevicesW`, `EnumDisplaySettingsExW`, and standard registry/WMI queries).
  - On **Linux (`linux`)**, hardware and display specifications are queried locally in read-only mode from `/proc/cpuinfo`, `/proc/meminfo`, `/sys/class/drm`, `xrandr`, `lspci`, and `df`.
- **Zero Personal Identifiable Information (PII) Stored or Transmitted**: Your Windows/Linux username, hostname, MAC address, serial numbers, and local file paths are never transmitted off your device.

---

## 2. Non-Invasive Game Scanning & Anti-Cheat Safety

- **No Memory Reading or Process Injection**: RigCheck Optimizer **never** attaches debuggers, injects DLLs/shared objects, hooks graphics APIs (`DirectX`, `Vulkan`, `OpenGL`), or reads process memory.
- **Safe Process Status Checks**: To display whether an installed game is currently `Running` or `Ready to Play`, the scanner performs a standard, non-invasive OS process list check (`tasklist` on Windows / `ps` on Linux) matching only the executable filename. This is 100% compatible with kernel and user-mode anti-cheat systems (Easy Anti-Cheat, BattlEye, Vanguard, Ricochet, VAC).
- **Read-Only Library Manifest Parsing**: Installed games are discovered exclusively by reading standard launcher manifest files (`appmanifest_*.acf`, `*.item`, `installed.json`, `*.yml`). Game installation directories and binaries are never modified automatically.

---

## 3. Explicit User-Gated Outbound Network Access (Firewall Consent Gate)

- **Default Offline Operation**: By default, all outbound price/deal queries in `src/price-finder.js` are **blocked** (`FIREWALL_PERMISSION_REQUIRED`).
- **Explicit Session Consent**: External HTTPS queries (TCP port `443`) are only executed after the user explicitly approves the in-app **Firewall Permission Prompt** for the current session.
- **Revocable at Any Time**: Users can revoke outbound network permission at any time from the UI (`Revoke Access`), immediately re-locking all external requests.
- **Strict Protocol & URL Sanitization**: External links opened via `rigcheck:open-external-url` are validated to allow only `https://` and `http://` schemes, preventing arbitrary protocol or command execution.

---

## 4. Electron Context Isolation & IPC Security

- **Context Isolation Enabled**: The Electron renderer process runs with `contextIsolation: true` and `nodeIntegration: false`.
- **Strict `contextBridge` Whitelist (`src/preload.js`)**: The UI (`public/app.js`) has zero direct access to Node.js primitives (`fs`, `child_process`, `os`) and can only invoke explicitly whitelisted IPC channels registered in `src/ipc-handlers.js`.

---

## 5. Cryptographically Verified Updates (`.rigpatch.json`)

- **Per-File & Bundle SHA-256 Verification**: Every `.rigpatch.json` patch bundle generated by `src/patcher.js` includes individual SHA-256 hashes for each file plus a master bundle SHA-256 signature.
- **Pre-Flight Tamper Rejection**: `validatePatchBundle` verifies all cryptographic hashes and CalVer progression before any file is written to disk. Any modified or corrupted payload is rejected immediately.
- **Automatic Atomic Backups**: Before applying a patch, `applyPatchBundle` saves a full snapshot of affected files in `dist/backups/` so users can roll back in one click (`npm run patch:rollback`).

---

## 6. Reporting Security Issues

If you discover a security or privacy vulnerability in RigCheck Optimizer:
1. Do **not** include personal system dumps or sensitive environment variables in public issues.
2. Open a security advisory or issue in the repository detailing the affected component (`src/`, `native/`, or `scripts/`) and steps to reproduce.
